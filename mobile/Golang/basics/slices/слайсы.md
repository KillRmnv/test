# Слайсы (Slices)

Слайс в Go — это **НЕ массив** и **НЕ контейнер данных**. Это **дескриптор** (представление), который "смотрит" на участок базового массива. Это ключевое отличие от Java `ArrayList`.

> [!abstract] Краткая суть
> Слайс = указатель + длина + ёмкость. Данные хранятся в массиве, слайс лишь описывает, какую часть этого массива мы видим.

Связано с: [[Основы языка]], [[Встроенные структуры данных]], [[Память и GC]]

## 1. Внутреннее устройство SliceHeader

Внутри Go слайс представлен структурой из 3 полей (24 байта на 64-битной системе):

```go
type SliceHeader struct {
    Data uintptr  // указатель на базовый массив
    Len  int      // длина (сколько элементов видно)
    Cap  int      // ёмкость (сколько всего доступно)
}
```

### Визуальная схема

```
┌─────────────────┐         ┌────────────────────────────────┐
│   Слайс `s`     │         │      Базовый массив            │
│  ┌───────────┐  │         │  [0] [1] [2] [3] [4] [5]       │
│  │ Data  ─────┼─┼────────▶│   2   3   5   7  11  13        │
│  ├───────────┤  │         └────────────────────────────────┘
│  │ Len = 6   │  │
│  ├───────────┤  │
│  │ Cap = 6   │  │
│  └───────────┘  │
└─────────────────┘
```

## 2. Разбор операций со слайсом

Исходный слайс: `s := []int{2, 3, 5, 7, 11, 13}` (len=6, cap=6)

### `s = s[:0]` — обнуление длины

```
┌─────────┐
│ Data ───┼──▶ [2, 3, 5, 7, 11, 13]  ← данные НЕ удалены!
│ Len = 0 │                           мы просто не видим их
│ Cap = 6 │
└─────────┘
```
**Результат:** `len=0 cap=6 []`

### `s = s[:4]` — расширение длины

```
┌─────────┐
│ Data ───┼──▶ [2, 3, 5, 7, | 11, 13]
│ Len = 4 │       ▲ видимая часть     ▲ скрытая
│ Cap = 6 │
└─────────┘
```
**Результат:** `len=4 cap=6 [2 3 5 7]`

### `s = s[2:]` — сдвиг начала (самое важное!)

```
┌─────────┐
│ Data ───┼──▶ [2, 3, | 5, 7, | 11, 13]
│ Len = 2 │         ▲ новая позиция Data
│ Cap = 4 │
└─────────┘
```
**Результат:** `len=2 cap=4 [5 7]`

> [!important] Почему `cap` упал с 6 до 4?
> `Cap` считается **от текущей позиции `Data`** до конца базового массива. Мы сдвинулись на 2 элемента вперёд, поэтому доступных элементов осталось 4.

## 3. Подводные камни (Критично!)

### ⚠️ Несколько слайсов на один массив

```go
a := []int{1, 2, 3, 4, 5}
b := a[1:4]  // b = [2, 3, 4]

b[0] = 99
fmt.Println(a)  // [1, 99, 3, 4, 5]  ← a тоже изменился!
```

> [!warning] Запомните
> Слайсинг **НЕ создаёт копию данных**. Оба слайса ссылаются на один и тот же массив в памяти.

### Как сделать настоящую копию:

```go
// Способ 1: copy()
newSlice := make([]int, len(oldSlice))
copy(newSlice, oldSlice)

// Способ 2: append с пустым слайсом
newSlice := append([]int{}, oldSlice...)

// Способ 3: slices.Clone (Go 1.21+)
import "slices"
newSlice := slices.Clone(oldSlice)
```

## 4. Рост ёмкости при `append`

Новый массив аллоцируется **только** когда ёмкости не хватает:

```go
s := []int{1, 2, 3}  // len=3, cap=3
s = append(s, 4)     // создаётся НОВЫЙ массив, cap=6
```

### Правила роста capacity:

| Текущий `cap` | Новый `cap` |
|:---:|:---:|
| `< 256` | `old * 2` |
| `>= 256` | `old * 1.25 + 192` |

> [!tip] Совет по производительности
> Если заранее знаете размер слайса, используйте `make([]T, 0, N)` — это сэкономит переаллокации.

## 5. Сравнение с Java

| Концепция | Java `ArrayList` | Go `slice` |
|:---|:---|:---|
| **Хранение данных** | Сам объект хранит массив | Дескриптор ссылается на массив |
| **Создание копии** | `new ArrayList<>(old)` | `copy()` или `slices.Clone()` |
| **Sublist** | `list.subList()` (view) | `s[low:high]` (тот же массив!) |
| **Передача в функцию** | Ссылка на объект | Копия дескриптора (но `Data` тот же) |
| **Ресайз** | Автоматический при `add()` | Только `append()` может увеличить |
| **Потокобезопасность** | `CopyOnWriteArrayList` | ❌ Нет, нужен `sync.Mutex` |

## 6. Практическое задание

Предскажите вывод, не запуская код:

```go
func main() {
    s := make([]int, 0, 5)       // len=0, cap=5
    s = append(s, 1, 2, 3)       // len=3, cap=5
    
    a := s[1:]                   // ?
    b := append(a, 4, 5, 6)      // ?
    
    fmt.Println("s:", s)
    fmt.Println("a:", a)
    fmt.Println("b:", b)
}
```

<details>
<summary>💡 Ответ</summary>

```
s: [1 2 3]
a: [2 3]
b: [2 3 4 5 6]
```

**Почему:**
- `a := s[1:]` → len=2, cap=4 (ссылается на тот же массив)
- `append(a, 4, 5, 6)` нужно добавить 3 элемента, но cap=4 хватает только на 2 (с учётом текущих 2 элементов). 
- Go создаёт **НОВЫЙ** массив для `b`, поэтому `s` и `a` остаются со старыми значениями.

</details>

## 7. Утечка памяти через слайсы

> [!danger] Важный паттерн
> Если большой слайс порезать на маленький, Go **НЕ освободит** память базового массива, пока маленький слайс жив.

```go
func getSmall() []byte {
    big := make([]byte, 1000000)  // 1 MB
    return big[:10]               // возвращаем 10 байт, но держим 1 MB!
}
```

**Решение:** делать явную копию нужной части.

```go
func getSmall() []byte {
    big := make([]byte, 1000000)
    result := make([]byte, 10)
    copy(result, big[:10])
    return result  // теперь big можно освободить GC
}
```

## Полезные функции (пакет `slices`, Go 1.21+)

```go
import "slices"

slices.Clone(s)           // глубокая копия
slices.Contains(s, val)   // есть ли элемент
slices.Index(s, val)      // индекс элемента
slices.Sort(s)            // сортировка
slices.Compact(s)         // убрать дубликаты подряд
slices.Reverse(s)         // реверс
```
