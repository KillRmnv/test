Внедрение и выполнение вредоносных скриптов через изображения — это классическая техника атаки.

В тестировании и безопасности под фразой «скрипт в картинке» обычно понимают **два разных сценария**:

1. **XSS через формат SVG** (векторная графика).
    
2. **Steganography & Polyglots** (скрытые данные в растровых форматах JPG/PNG).
    

Ниже подробно разобрано, как это работает, чем отличается и как тестируется.

## 1. SVG-файлы: Прямое выполнение XSS (Самый частый вектор)

В отличие от JPG или PNG, **SVG (Scalable Vector Graphics)** — это не бинарный файл с пикселями, а обычный **XML-документ**.

Согласно спецификации W3C, SVG поддеживает внутри себя HTML-теги и встроенные теги `<script>`.

### Как выглядит уязвимый SVG:

Если сохранить этот текст в файл `avatar.svg` и загрузить на уязвимый сайт:

### Когда скрипт сработает, а когда нет?

- 🔴 **Сработает:** Если сервер отдаёт SVG с заголовком `Content-Type: image/svg+xml`, и пользователь открывает файл напрямую в браузере (например, нажав _«Открыть изображение в новой вкладке»_ или если файл рендерится через `<embed>`, `<iframe>`, `<object>`).
    
- 🟢 **НЕ сработает:** Если картинка отображается через стандартный HTML-тег `<img src="avatar.svg">`. Браузеры из соображений безопасности **блокируют** выполнение любых скриптов внутри тега `<img>`.
    

## 2. Polyglot Files (Полиглоты: JPG/PNG + JavaScript)

**Полиглот** — это специально сформированный файл, который одновременно является валидной картинкой (например, JPG) и валидным JavaScript-кодом.

### Как это устроено:

Заголовки бинарных файлов (JPEG/PNG) содержат метаданные (EXIF: комментарии, модель камеры, GPS-координаты). Злоумышленник записывает JS-код прямо в поле метаданных файла:

Bash

```
# Добавление JS-кода в EXIF-комментарий JPEG-файла с помощью exiftool
exiftool -Comment="<script>alert('EXIF XSS')</script>" photo.jpg
```

### Как это эксплуатируется:

Сам по себе файл `photo.jpg` не выполнит скрипт при просмотре. Однако атака срабатывает в следующих случаях:

1. **Сервер вычитывает EXIF-метаданные:** Если веб-приложение читает имя фотографа или описание из EXIF и без экранирования выводит это на страницу (например, _«Автор фото: `<script>...</script>`»_), происходит **Stored XSS**.
    
2. **Использование как библиотеки (MIME-sniffing):** Если на сервере есть уязвимость File Upload, и приложение разрешает подключать скрипты, файл могут подключить через тег скрипта:
    
    HTML
    
    ```
    <script src="/uploads/photo.jpg"></script>
    ```
    
    Браузер считывает байты файлового заголовка, игнорирует "мусор" изображения и находит зашитый внутрь исполняемый JS-блок.
    

## 3. Стеганография (Steganography)

Это скрытие payload (payload может быть чем угодно — от JS-кода до вредоносного `.exe`) в наименее значимых битах пикселей изображения (LSB — Least Significant Bit).

- **Визуально:** Картинка выглядит абсолютно нормально, человеческий глаз не видит изменений.
    
- **Использование:** Сам по себе файл не исполняется. Чтобы вытащить скрипт, на клиенте или сервере должен быть другой уязвимый код (лоадер), который вычитывает пиксели через Canvas API (`getImageData()`), декодирует их обратно в строку и выполняет её через `eval()`.
    
- **Цель:** Обход систем обнаружения вторжений (IDS), фаерволов (WAF) и антивирусов.
    

## Чек-лист для QA: Как тестировать загрузку изображений

При проверке формы загрузки аватарок, документов или медиафайлов обращайте внимание на следующие кейсы:

1. **Загрузка SVG-файлов:**
    
    - Попробуйте загрузить `.svg` с тегом `<script>alert(1)</script>`.
        
    - Проверьте, под каким `Content-Type` сервер отдаёт этот файл.
        
    - Откройте прямую ссылку на загруженный файл в новой вкладке.
        
2. **Манипуляция расширением и MIME-типом:**
    
    - Переименование: `payload.php.jpg`, `payload.svg.png`, `script.js.png`.
        
    - Замена `Content-Type` в перехваченном запросе (через DevTools/Burp Suite): отправить JS-файл, но указать `Content-Type: image/png`.
        
3. **Запись XSS в EXIF-метаданные:**
    
    - Внедрить `<script>alert('EXIF')</script>` в поля `Artist`, `Make`, `Model` или `Comment` растрового изображения (JPG/PNG).
        
    - Проверить, отображаются ли эти данные где-либо в интерфейсе админки или профиля.
        
4. **Защита и валидация (Что должно быть на бэкенде):**
    
    - **Пересборка/Ресайз (Re-encoding):** Сервер должен прогонять загруженные растровые картинки через графическую библиотеку (например, `ImageIO` в Java или `ImageMagick`) и пересохранять их. Это начисто удаляет все чужеродные байты, EXIF-теги и скрытые скрипты.
        
    - **Санитизация SVG:** Использование специализированных библиотек (например, DOMPurify) для вырезания `<script>` и опасных атрибутов из SVG.
        
    - **Заголовки безопасности:** Сервер должен отдавать загруженный контент с заголовками `Content-Disposition: attachment` (принудительное скачивание вместо открытия в браузере) или `X-Content-Type-Options: nosniff`.
